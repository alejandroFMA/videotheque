# 3D Film Case Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Do not commit.** The repo owner reviews and commits by hand. Leave every change unstaged.

**Goal:** Replace the static pulled-out case with a Three.js VHS case that flies out of its slot, turns 360° and shows a 90s back cover built from new cached TMDB fields.

**Architecture:** Four new `films` columns are filled server-side by the existing add endpoint (and once by a local backfill script). The slot carries them to the browser as one JSON attribute. Pure maths and text layout live in small tested modules; canvas drawing and the Three.js scene live in a browser module loaded with a dynamic `import()` on the first open, inside the existing `<dialog>`. Without WebGL the current static view is used.

**Tech Stack:** Astro 7 SSR, Supabase Postgres, Vitest (node env), Three.js (new npm dependency), plain TypeScript in `<script>` tags.

**Spec:** `docs/superpowers/specs/2026-11-16-3d-film-case-design.md`

## Global Constraints

- Rendering a shelf and opening a case never call TMDB. Every face comes from the `films` cache.
- The browser writes only `spine_color`. New columns are written by `POST /api/shelves/[id]/films` on insert and by the backfill script. No new update path in the app, no new RLS policy.
- No invented content: a missing field leaves that part of the back out.
- Every user-facing string lives in `src/constants/`. Code, comments and identifiers in English.
- No magic values inline (`.claude/.rules/constants-and-types.md`): module-owned constants stay co-located in their module.
- Three.js only for the pulled-out case, loaded with dynamic `import()` on first open. The shelf stays CSS/DOM.
- Images come from `image.tmdb.org`, never rehosted. Texture loads use `crossOrigin = 'anonymous'`. Sizes: front poster `w780`, backdrops `w780`, company logos `w185`. Never `w154` (spine colour) or `w500` (static fallback `<img>`) for a texture.
- Sleeve proportions: front width = 0.56 × height, thickness = 0.14 × height. Rest angle 0.35 rad, spine side towards the viewer.
- No VHS logo: the band shows the word `VHS` in Big Shoulders inside a thin rule box.
- Canvas text uses the self-hosted faces in `public/fonts/` (Big Shoulders, Archivo, Archivo Narrow), awaited with `document.fonts.load` before drawing.
- No inertia: the case turns only while dragged, then settles on the nearest face in about 0.5 s.

## Review Focus

1. **A film cached before this step** (empty new columns) must open with a degraded back (poster crop instead of scenes, no billing block, no logos), never a crash or blank texture. Pinned in Task 3 (`parseCaseDetails` on missing/invalid input) and checked by hand in Task 6.
2. **Long names and titles** (*The Lord of the Rings: The Return of the King*, six long cast names) must wrap without cutting a name or running off the canvas. Pinned in Task 3 (`wrapItems` tests).
3. **Many full turns, then close:** the case must go home the short way, not unwind every turn. Pinned in Task 4 (`homeAngle`).
4. **The bookcase zoomed on a large monitor** (≥1440 px, CSS `zoom`): the flight must start and end exactly on the spine. Pinned in Task 4 (`poseFromRect` uses the on-screen rect only) and checked by hand at 1440/1800/2200 px in Task 6.
5. **Clicks while an animation is running** (double click on a spine, Esc during the flight, drag during the settle) are ignored, not stacked. Checked by hand in Task 6. The controller keeps one `busy` flag.

### Task 4: Case pose maths

**Files:**
- Create: `src/lib/case-pose.ts`
- Test: `test/case-pose.test.ts`

**Interfaces:**
- Produces (all exported from `case-pose.ts`):
  - `interface Pose { x: number; y: number; z: number; s: number; ry: number; d: number }`. World units, scale, Y rotation in radians, `d` = depth multiplier.
  - Constants: `CASE_WIDTH = 0.56`, `CASE_DEPTH = 0.14`, `REST_RY = 0.35`, `FOV_DEG = 22`, `CAMERA_Z = 10`, `VISIBLE_HEIGHT` (derived: `2 * CAMERA_Z * tan(FOV/2)`), `NARROW_PX = 760`, `DRAG_RAD_PER_PX = 0.009`.
  - `lerpPose(a: Pose, b: Pose, t: number): Pose`
  - `poseFromRect(rect: { left: number; top: number; width: number; height: number }, viewport: { width: number; height: number }): Pose`. Spine-on (`ry = π/2`), centred on the rect, `s` = rect height in world units, `d = (width / height) / CASE_DEPTH`.
  - `interface CaseLayout { cx: number; cy: number; caseHeight: number; narrow: boolean }` and `caseLayout(viewport): CaseLayout`. Desktop: `caseHeight = min(700, 0.86·h, 0.6·w)`, `cx = w/2 − min(210, 0.22·w)`, `cy = h/2`. Narrow (< 760): `caseHeight = min(0.56·h, 460)`, `cx = w/2`, `cy = 40 + caseHeight/2`.
  - `centrePose(layout: CaseLayout, viewport, ry = REST_RY): Pose` with `d = 1`.
  - `nearestFace(ry: number): number`. The nearest of `REST_RY + 2πk` (front) and `π − REST_RY + 2πk` (back).
  - `flipTarget(ry: number): number`. From the nearest face to the other one, continuing in the same direction.
  - `homeAngle(ry: number): number`. `π/2 + 2πk` nearest to `ry`.
  - `isFront(ry: number): boolean`

- [ ] **Step 1: Install Three.js**

Run: `npm install three` and `npm install -D @types/three`.
Expected: both added to `package.json` with exact versions, as the repo pins its other dependencies.

- [ ] **Step 2: Build the scene in `case-scene.ts`**

- **Renderer, created once:** antialias, alpha, pixel ratio capped at 2, `NeutralToneMapping`, soft shadow map.
- **Scene:** a `PMREMGenerator` + `RoomEnvironment` environment at intensity 0.55. A key `DirectionalLight` `0xfff3e2` at 2.6, position (−3, 4, 9), casting a 2048² shadow. A rim light `0xbfd4ff` at 0.7, position (5, 1, −4). A `ShadowMaterial` plane at opacity 0.38, kept at `pose.z − 0.14·pose.s`.
- **Camera:** `PerspectiveCamera(FOV_DEG)` at z = `CAMERA_Z`.
- **Mesh:** `BoxGeometry(CASE_WIDTH, 1, CASE_DEPTH)` with six `MeshPhysicalMaterial` faces (roughness 0.6, clearcoat 1, clearcoatRoughness 0.12), in the order +x side, −x spine, +y edge, −y edge, +z front, −z back. The front poster texture is cropped to 0.56 with `repeat.x` and `offset.x`.
- **Applying a pose:** `scale.set(s, s, s·d)`.
- **Images:** load with `crossOrigin = 'anonymous'`, treat one as missing after 4 s or on error, and cache each image by URL.
- **Order:** start the flight once the poster and the fonts are ready. Draw the back when the backdrops and logos settle, then swap its map in.
- **Close:** dispose the geometry and the textures, and stop the animation loop.

- [ ] **Step 3: The motion**

- **Open:**
  - First 20 % of 1050 ms: lift by 0.24·s and come 0.4·s towards the viewer.
  - Remaining 80 %: ease-in-out to `centrePose`. `ry` goes from π/2 to `REST_RY` slightly faster than the position, `d` goes to 1, and an arc adds `sin(u·π)·0.5·s` to z.
  - Hide the spine with the existing `.placeholder`-style visibility, or a new class.
- **Drag:** `ry += dx · DRAG_RAD_PER_PX`, unbounded, only while the pointer is down. On release, ease out over about 500 ms to `nearestFace(ry)`. In the full-viewport layer, a pointer-down that misses the case (raycast) and does not move counts as a click outside and closes.
- **Flip:** ease to `flipTarget(ry)`.
- **Close** (850 ms): the first 80 % eases to the lifted home pose with `ry → homeAngle(ry)`; the last 20 % drops into the slot. Then show the spine again and return focus to it.
- **Reduced motion** (`prefers-reduced-motion: reduce`): every duration is 0.
- **`busy`:** true while any tween runs. `open`, `flip`, `close` and drag starts are ignored while it is true.
